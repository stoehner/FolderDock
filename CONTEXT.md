# CONTEXT.md — FolderDock domain and architecture vocabulary

Shared language for agents and humans working on this codebase. Terms in the renderer, main process, docs, and tests mean exactly what is written here.

## Domain terms

- **Library**: the user's whole file universe. A real directory on disk (the **root**), defaulting to `Documents\FolderDock`. Nothing is stored anywhere else; every item in the UI maps to a real file or folder inside it.
- **Root**: the library's directory on disk. Changeable in Settings; overridable for tests with `FOLDERDOCK_ROOT`.
- **Collection**: a real subfolder of the root, drawn as a glass folder card. The user-facing word for a folder inside the library is always "collection."
- **Unsorted**: the virtual collection for files sitting loose in the root. It has no folder on disk; its files are the root's loose files. It cannot be renamed, deleted, or reordered.
- **Art style**: the color treatment of a collection card. Named ids live in `src/shared/art-values.ts` (grouped Classics/Vivid/Deep in `lib/art.ts`); a 6-digit hex value is a custom color, synthesized into a glass gradient by `customArtFor`. Pinned styles live in `folderArt`; unpinned collections follow the name hash or the `newFolderArt` setting. Custom colors picked through the in-app picker are remembered in the `customColors` palette (deletable; deleting a palette entry never unpins a collection, since each collection stores its own hex).
- **Diagnostics ledger**: the local-only error log. `src/main/logger.ts` appends timestamped `{ISO} LEVEL tag: message` lines to `%APPDATA%\FolderDock\logs\main.log` (rotated into `main.1.log` past 1 MB) with fire-and-forget, guarded writes — logging can hang or crash nothing. Tags name the origin: `boot`, `heartbeat`, `main` (uncaught exceptions / unhandled rejections), `ipc`, `watcher`, `updates`, `drag` (native carrier starts), `ui` (modal breadcrumbs), `drag-out` (drag-out breadcrumbs), `renderer-console` (webContents messages of severity ≥ 2), `window-error` and `unhandled-rejection` (renderer report via the one-way `log:report` SEND channel, host-validated), `renderer` (60 s renderer heartbeats), `window`, `log`, `shutdown`, `snapshot`. The window's `unresponsive` event writes `hang-snapshot.json` beside the log: reason, versions, and the last 35 lines, so a force-closed freeze stays explainable. `crashReporter` runs with an empty submit URL and `uploadToServer: false`; nothing — lines, snapshots, dumps — ever leaves the machine. The detail level is the `logLevel` pref (`basic` by default; `verbose` additionally records per-call `ipc` lines and scan-step lines).
- **Paper sheet**: the document-styled preview card on a collection, and the drag-out affordance for one file.
- **Shelf**: the dashboard grid of collection cards.
- **Collection page**: the full-window view of one collection's contents. Clicking a folder card opens it (creating a collection opens it too); the back button or Esc returns to the shelf. The search box and filter chips apply to the page's file list, and dropping files on the page moves them into that collection. `openFolder` names the collection whose page is open. The INSIDE FOLDER panel under a card only expands during search, as an inline results peek. The `fontSize` setting (Small/Medium/Large, default Medium) scales the page; the cards-shrink `--grid-zoom` never applies to it.
- **Drop zone**: the dashed strip under the toolbar. Dropping files from Explorer there moves them into the library using the same target rule as shelf-background drops (open collection, else first collection, else Unsorted); clicking it opens the import picker.
- **Import dedupe**: a file being imported (drop, drop zone, or picker) that is byte-identical — same size, same bytes — to one already in the target collection is skipped with a toast instead of being added as a ` (n)` copy. The scope is the target collection only, so identical content can still be brought into a different collection deliberately. Names do not matter; content does. This is what breaks the drag-out → drag-back duplicate loop.
- **Move out of library**: the file context menu can move one file out of the library into a destination chosen in a dialog (`file:chooseMoveOut` picks the folder, `file:moveOut` performs the move). Same drive: rename. Different drive: copy, then the library copy goes to the Recycle Bin — if recycling fails the copy stays and a toast says so. Name collisions at the destination get a ` (n)` suffix, matching imports. A destination inside the library is refused (Move to collection covers that).
- **Drag out (move out)**: every file drag — a paper sheet, a file row, single or with the current selection — hands the real file to the native main-process carrier (`file:startDrag`); no HTML5 drag session starts, so no drag event gets to decide afterwards what the OS did. Chromium's `dragend.dropEffect` is a guess on Windows and was measured (2026-11-01) reporting `move` and `copy` even when the target refused the drop (crbug 41183574), so the verdict comes only from disk — and the carrier can only ever deliver copies: Electron starts the OLE drag with allowed operations copy | link (`drag_util_views.cc` line 47, v44.10.1) and `startDrag` exposes no way to offer move, so external drops land as copies on any drive (the old "same-drive drops default to move" premise holds for Explorer sources only, not an Electron app source — reported from daily use 2026-11-01, root-caused 2026-11-02). After a single-file drag starts, a settle scan chain (first scan 1.2 s after the drag, step scans every 4 s, at most 3 scans) reads the library snapshot: file gone from the library root and its name listed nowhere else means Windows really moved it away (a Recycle-bin target or a future carrier) — the entry is applied and a toast reports `"name" moved out of the library`. The file still present once the scans cap out means a copy delivery, refused drop, or Esc — states the disk cannot separate, so the user's declared drag intent resolves it: a plain drag keeps with one educational toast (`"...still in your library — hold Shift..."`); Ctrl/Alt or a multi-selection drag (explicit copy/shortcut intent) keeps silently; Shift (a move request) opens a confirm modal whose confirm recycles the library copy into the Recycle Bin (recoverable) with the same `"name" moved out of the library` toast and whose Cancel keeps silently — no scan verdict ever recycles on a guess. A scan that finds the name re-homed in another collection stops quietly: dropping back onto a FolderDock surface rides the import path now (there is no internal drag marker anymore), so the import's own toast reports the move.
- **Favorites**: files and collections the user starred via the star button on a file row or collection card. The Favorites filter shows starred collections in full plus starred files. `starred` holds file relPaths and collection names. The file context menu has no favorites item — the row's star button is the only toggle.
- **Bridge**: the typed renderer-to-main interface (`FolderDockBridge` in `src/shared/api.ts`, exposed as `window.folderdock`). All cross-process calls go through it.
- **Channel map**: `src/shared/channels.ts`. The single place that names every IPC channel; preload and the main handlers both read from it.
- **Settings**: persisted user preferences owned by the preferences module (`src/renderer/src/state/prefs.ts`). Fields: theme, alwaysOnTop, viewSize, fontSize, cardColumns, fileSort, closeToTray, confirmDelete, autoCheckUpdates, hoverDelay, logLevel, newFolderArt, backupLocation, customColors. One seam: `boot` / `patch` / `setTheme` / `setViewSize` / `resetSettings`, plus the update state feed (`updates:getState` channels).
- **Preferences module**: `state/prefs.ts`. Deep module that owns settings hydration, validation-aware persistence, and the DOM consequences (`body.light`, `body.compact`, the `--grid-zoom` cards-shrink-to-fit variable) including the system-theme media listener and the window resize listener.
- **Backup**: a manual, timestamped folder copy of the whole library into the backup location (the `backupLocation` setting, default `Z:\REA-Backups`), triggered from Settings or the Backups dialog. A backup run copies only; old backups can be deleted from the Backups dialog, which moves the backup folder to the Recycle Bin like every delete.
- **Library view state**: folderOrder, folderArt, starred, openFolder. Persisted preferences that describe a view of the library rather than app behavior. They deliberately live in the session store (`state/ui.ts`), not the preferences module, and are pruned by the main process on scan.
- **Session state**: everything else in `state/ui.ts` — modals, selection, search, editor, preview, toasts. Never persisted.
- **Excerpt**: the plain-text summary of a file, shown on paper sheets and hover summaries. Cached per file, keyed by mtime (`state/excerpts.ts`).
- **Content match**: a search result from inside file contents (`searchContent`), rendered as a snippet on the file row.
- **Orphan preference**: a persisted entry naming a collection that no longer exists. The main process prunes these during `library:scan` via `prunePrefs`.
- **Dialog router**: `components/ModalLayer.tsx` maps a `Modal` union member to one module in `components/modals/`. Each dialog is its own module; `modals/kit.tsx` holds Head, Foot, and Toggle. The file preview is a separate blocking overlay (`PreviewModal`) driven by `previewRelPath` session state, not a modal-union member; it never resizes the window.

## Invariants

- Files are real on disk under the root, never in app/browser storage.
- Deleting moves to the Windows Recycle Bin.
- Importing files from outside the library (drops, the drop zone, the import picker) moves them: same-volume rename when possible, otherwise copy into the library and recycle the source. A byte-identical duplicate of a file already in the target collection is skipped (import dedupe), so dragging a library file out and dropping it back in cannot multiply ` (n)` copies.
- Moving a file out of the library ("Move out of library…") is the import move in reverse. Drag-out can never be a true OS move — the Electron carrier offers Windows copy | link only — so move-out is user intent: a Shift drag opens the confirm modal that recycles the library copy (Recycle Bin, recoverable); plain drags keep with an educational toast naming Shift, Ctrl/Alt/multi keep silently; a scan that proves a real move-away (Recycle-bin target, future carrier) still wins from disk. A drop back onto a FolderDock surface moves the file through the import path instead. Multi-selection drags remain copies (native drag path).
- The UI stays faithful to the glass-folder card design (`docs/reference/FolderDock_Interactive_v2.html`), with the 182px rescaled values in `src/renderer/src/styles/folder.css`.
- Installers are unsigned; SmartScreen warnings are expected.
- The diagnostics ledger, its hang snapshots, and crash dumps are local-only: no submit URL, no upload, no telemetry. A diagnostics aid must never become a data channel.
- All IPC channel names come from the channel map; never write a channel string literal elsewhere.
